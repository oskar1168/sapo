Sapo 작업 리뷰

작성일: 2026-06-23 / 주제: 여행 기본 데이터 분리, Metro 캐시 이슈 확인

요약

오늘 작업은 화면 코드에서 커질 가능성이 높은 여행 기본 데이터를 도시별 파일로 나누는 데 집중했습니다. 기존 import 경로는 유지하면서 내부 데이터만 폴더 단위로 분리해, 앞으로 도시별 추천 일정과 지역 가이드를 추가할 때 한 파일이 과도하게 커지는 문제를 줄였습니다.

주요 변경

1. 도시 기본 템플릿 분리

  • CITY_TEMPLATES를 src/data/city-templates 폴더로 이동했습니다.
  • 삿포로, 도쿄, 오사카 기본 템플릿을 도시별 파일로 나눴습니다.
  • src/constants/travelData.ts에서는 기존처럼 CITY_TEMPLATES를 export하도록 호환성을 유지했습니다.

2. 추천 일정 프리셋 분리

  • src/data/itineraryPresets.ts의 대형 데이터를 src/data/itinerary-presets 폴더로 분리했습니다.
  • 홋카이도, 도쿄, 오사카, 후쿠오카, 오키나와, 나고야 프리셋을 도시별 파일로 나눴습니다.
  • buildPresetTripDays, hasItineraryPreset 공개 API는 그대로 유지했습니다.

3. 지역 탐색 가이드 분리

  • src/data/regionGuides.ts의 지역 가이드 데이터를 src/data/region-guides 폴더로 분리했습니다.
  • 도시별 지역 가이드가 독립 파일로 관리되도록 바꿨습니다.
  • getRegionGuide와 REGION_GUIDES export는 기존 사용처가 깨지지 않도록 유지했습니다.

검증

  • npm exec tsc -- --noEmit 통과
  • npm run lint 통과
  • http://localhost:8083에서 Expo web 앱 정상 응답 확인

메모

데이터 파일을 새 폴더로 대량 생성한 뒤 Metro가 기존 캐시로 인해 새 파일을 찾지 못하는 문제가 있었습니다. 기존 서버를 종료하고 expo start --web --clear로 재시작해 정상 동작을 확인했습니다.
